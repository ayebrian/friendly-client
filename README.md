# Friendly Client

TypeScript/React клиент для существующей сети Friendly. Публичная главная страница,
регистрация и вход по email, лента, профиль, друзья и приглашения работают через API Friendly.
TypeScript включён в strict-режиме. Демо-режима в приложении нет.

```sh
npm ci
npm run dev
```

Открыть адрес из вывода Vite (обычно http://localhost:5173). Главная страница — лендинг;
`/login` — вход, `/signup` — создание аккаунта. После регистрации привяжите email
в Settings, чтобы сохранить возможность входа с другого устройства.

Приглашение создаётся в **Account → Invite a friend** через `/friends/generate`.
Ссылка и QR ведут на `/invite#?reference=…` текущего сайта. Получатель входит или
создаёт аккаунт, затем явно нажимает **Accept invitation**. Приглашение сохраняется
в URL fragment при переходах и перезагрузке; оно не отправляется серверу страницы.
Старые форматы `/#?reference=…` и `/redirect/…` также поддерживаются.
**Refresh invitation** вызывает `/friends/generate/force` и заменяет предыдущую ссылку.
Ошибки сети, истечение приглашения и собственная ссылка показываются в интерфейсе.

Реальный вход использует почту, уже привязанную к аккаунту Friendly. Код — 8 цифр.
Без аккаунта реальная авторизация и содержимое уведомлений не проверены.
Базовый URL по умолчанию https://api.getfriend.ly; переопределение через
`VITE_API_BASE_URL` в `.env.local` (это публичная настройка, не место для секретов).

## Структура проекта

- `src/app` — сборка приложения, провайдеры и маршруты.
- `src/domain` — типы и контракт API, без зависимостей от UI.
- `src/infrastructure` — настоящий API, проверка ответов и сессия.
- `src/features` — экраны и логика входа, уведомлений, профиля и обсуждения.
- `src/shared` — готовые UI-компоненты и общие состояния.

Экраны реализованы в TSX. `index.html` — входная точка Vite.

## Готовые библиотеки

- shadcn/ui (Radix): кнопки, поля, вкладки, меню аккаунта, подсказки, аватары,
  бейджи и состояния загрузки. Общие компоненты лежат в `src/shared/ui`.
- Tailwind CSS 4: оформление компонентов; цвета, типографика и радиусы задаются
  одной темой в `src/app/styles.css`.
- React Hook Form + Zod: формы и проверка ввода.
- Sonner: уведомления внутри окна со ссылкой на события.
- TanStack Query: запросы, кеш и синхронизация; React Router: маршруты;
  Lucide: иконки.

Добавить готовый компонент: `npx shadcn@latest add dialog` (или другой компонент).
`components.json` направляет генератор в общую библиотеку; бизнес-логика остаётся
в features. Библиотеки подключаем под рабочий сценарий, а не целиком заранее.

## Медиа в публикациях

В редакторе поста, ответа и редактирования кнопка **Media** открывает выбор нескольких
файлов. Фото/GIF, видео и аудио можно также вставить в поле из буфера обмена (Ctrl+V
на компьютере, вставка из клавиатуры на Android). Кнопка **Paste** доступна в браузерах,
которые поддерживают чтение медиа из буфера по запросу пользователя.

Лимит клиента — 10 вложений, до 5 MB на файл. Превью и удаление доступны до отправки;
пост можно отправить без текста. Файлы загружаются при отправке. При ошибке черновик
сохраняется, повторная отправка использует уже загруженные файлы. Уход со страницы,
выход и истечение сессии отменяют загрузку.

Внешние изображения, видео и аудио из текста поста загружаются после нажатия
**Load image/video/audio**. До нажатия показывается домен источника. Файлы из
`/files/download/` настроенного API Friendly, медиа того же origin и локальные
blob-превью открываются сразу. При ошибке доступна повторная попытка. Одобрение
сохраняется при обновлении поста, но изменение URL требует нового нажатия.
Если настроен image proxy, внешние HTTPS-картинки загружаются автоматически через
него. Ошибка proxy оставляет кнопку Retry; прямой загрузки в обход proxy нет.
Видео и аудио продолжают требовать нажатия.

Редактор использует rich contenteditable с вводом обычного текста, поскольку Chromium
предлагает Android-клавиатуре вставку изображений только в richly editable поле.
Обрабатываются `paste` и `beforeinput` без привязки к клавишам. Проверены настоящая
вставка Ctrl+V и сценарий событий Android в Chromium на 1440/360px; физическое
устройство с Gboard не проверено.

## Image proxy на Workers

Worker и инструкция публикации находятся в [workers/image-proxy](workers/image-proxy/README.md).
Он принимает публичные HTTPS-изображения с любых доменов, проверяет DNS, redirects,
тип и сигнатуру файла, передаёт тело потоком и ограничивает размер до 5 MB.
Поддерживает PNG, JPEG, GIF, WebP и AVIF. Данные авторизации клиента в источник не отправляются.

```sh
npm run proxy:dev
VITE_IMAGE_PROXY_URL=http://127.0.0.1:8787/image npm run dev -- --port 5176
```

Для production сначала опубликовать Worker в аккаунте Friendly, затем установить
`VITE_IMAGE_PROXY_URL` в Pages на адрес Worker с путём `/image` и пересобрать клиент.
Пустая настройка сохраняет загрузку внешних медиа по нажатию.

## Проверки

```sh
npm run check
npm run build
npm run proxy:build
```

GitHub Actions запускает те же проверки на push в main и на pull request.
`check` включает тесты Worker в runtime Cloudflare; `proxy:build` проверяет
типы и упаковку с `wrangler deploy --dry-run`, без публикации.

## Заголовки production

Сборка создаёт `dist/_headers` для Cloudflare Pages: CSP, запрет iframe,
`nosniff` и `Referrer-Policy: no-referrer`. Загружать нужно весь каталог `dist`.
Для другого статического хостинга те же заголовки необходимо настроить в его
конфигурации; наличие файла само по себе там не гарантирует их применение.
`vite preview` применяет сгенерированные заголовки для локальной проверки сборки.

CSP разрешает скрипты с собственного origin и ранний inline-скрипт темы по SHA-256
хешу финального HTML. `unsafe-inline` и `unsafe-eval` для скриптов не разрешены;
оптимизация JIT в Zod отключена до создания схем. Для стилей разрешён inline,
поскольку Radix создаёт стили блокировки прокрутки, а React использует style-атрибуты.
Сетевые API ограничены настроенным Friendly API и двумя endpoint Firebase push.
Хеш и origin API пересчитываются при каждой сборке; HTML и `_headers` нужно
публиковать из одной сборки.

Схема модулей и решения: [docs/architecture.md](docs/architecture.md).
Следующие срезы: полноценные обсуждения с пагинацией, публикации, друзья и
редактирование профиля. Сейчас интерфейс содержит только реализованные разделы.

## Проверка

```sh
npm run check
npm run build
```

Интеграционные проверки приглашений проходят через настоящий HTTP-адаптер
с перехваченными ответами: вход, регистрация, перезагрузка, создание и замена ссылки,
принятие, ошибки и отмена запросов. Фикстуры для остальных UI-проверок находятся
в `src/app/fixture-gateway.test-utils.ts` и не входят в приложение. Проверка
реального добавления друзей на сервере требует двух аккаунтов Friendly.
