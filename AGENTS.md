# Работа над Friendly Client

- Корень композиции — `src/app`. Только он выбирает реальные или демо-адаптеры.
- `domain` не зависит от React, HTTP и внешних библиотек.
- `features` используют контракт `FriendlyGateway` и общие примитивы из `shared`.
  Не импортировать `infrastructure`, `app` или соседние features.
- UI-примитивы брать из shadcn/ui в `shared/ui`; новые добавлять CLI через
  `components.json`. Не дублировать кнопки, поля, меню и вкладки вручную.
- Формы — React Hook Form + Zod, сообщения внутри окна — Sonner.
- Оформление примитивов — Tailwind и общие токены темы; CSS экрана отвечает за композицию.
- HTTP, wire-форматы и проверка ответов находятся в `infrastructure`.
- Серверные данные хранятся в TanStack Query, локальное состояние интерфейса — в React.
  Не заводить второй кеш уведомлений или счётчика.
- Синхронизация уведомлений живёт выше маршрутов и работает без разрешения push.
  Неполная история не должна выдавать точный общий счётчик.
- Выход и истечение сессии отменяют операции и очищают кеш аккаунта.
- Не добавлять неработающие разделы меню. Демо-данные всегда явно обозначены.
- Токен API живёт только в HttpOnly cookie прокси `/api` (`bff/proxy.ts`, Pages Function
  `functions/api/[[path]].ts`). Клиент не получает, не читает и не хранит токен: ни в
  исходниках, URL и логах, ни в localStorage/sessionStorage. Запросы к API идут только
  через `/api`; медиа по capability URL `/files/download/…` загружаются напрямую из API.
- Изменения прокси сопровождать проверками в `bff/proxy.test.ts`: токен не попадает в тело
  ответа, заголовки и cookie, а изменяющие запросы с чужого Origin отклоняются.
- Для новых сценариев с сетевыми ошибками, отменой или состоянием аккаунта писать
  содержательные проверки. Для косметических правок достаточно проверки интерфейса.
- Перед завершением изменений запускать `npm run check` и `npm run build`.
- При изменении UI проверять браузер на 1440px и 360px, включая ошибки и пустые состояния.
